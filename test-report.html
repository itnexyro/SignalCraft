5. Security Review

  • Passwords are hashed using Node.js scrypt; raw passwords are not stored.
  • Gmail OAuth token payloads are encrypted with AES-256-GCM before persistence.
  • Production dispatch uses randomized 15–45 second delays as required by the PRD.
  • Failed recipients retain an error log and can be retried individually.
  • Secrets are configured through environment variables rather than source code.
Production requirement: replace the development encryption fallback with a long random APP_ENCRYPTION_KEY, use HTTPS, replace local JSON persistence with PostgreSQL/Prisma, and use secure server sessions instead of in-memory sessions.

7. Known Limitations & Next Steps

  1. Configure Google Cloud OAuth credentials and redirect URI before real Gmail sending.
  2. Set DEMO_MODE=false only after Gmail credentials are configured.
  3. Add an LLM provider key and server-side rewrite endpoint for unrestricted natural-language copilot commands.
  4. Replace CSV-only parsing with SheetJS for Excel support.
  5. Migrate data/store.json to PostgreSQL/Prisma for multi-user production use.
  6. Connect the frontend session token to backend API calls for full end-to-end persistence.
